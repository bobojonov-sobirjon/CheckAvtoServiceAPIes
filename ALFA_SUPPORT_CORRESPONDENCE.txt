Тема: Re: лог getTemplateDetails.do

Добрый день!

Ниже — фиксация последнего обращения к платёжному шлюзу (продуктив).

1) Исходящий запрос с нашего backend на шлюз

Метод: POST
URL: https://pay.alfabank.ru/payment/rest/templates/getTemplateDetails.do
Content-Type: application/x-www-form-urlencoded

Тело (application/x-www-form-urlencoded, одна строка для наглядности):

templateId=BS1A003T9OBLQLD499DOHMC28RE9OHG7&userName=45760700-api&password=***&language=ru

(пароль в переписке не приводим; в логах сервера хранится маскированно; фактическая пара — как в личном кабинете / .env; при необходимости для getTemplateDetails используется отдельная пара ALFA_TEMPLATES_DETAILS_* из .env)

Время запроса (МСК): <УКАЖИТЕ_САМИ_ПОСЛЕ_ТЕСТА_например_2026-04-11_15_42_10>

2) Ответ платёжного шлюза

HTTP статус: 200 OK
Content-Type: application/json (как приходит от шлюза)

Тело ответа (фактический пример):

{
  "errorCode": 5,
  "errorMessage": "Доступ запрещён"
}

3) Контекст

createTemplate.do для того же контура и логина выполняется успешно; templateId BS1A003T9OBLQLD499DOHMC28RE9OHG7 совпадает с шаблоном, отображаемым в личном кабинете.

Просим по вашим логам подтвердить получение запроса и причину errorCode 5 для getTemplateDetails при успешном create.

--------------------------------------------------------------------------------
Б) КРАТКО: ЧТО ДЕЛАЕМ И В ЧЁМ ПРОБЛЕМА
--------------------------------------------------------------------------------

Проект: мобильное приложение + backend (CheckAvto), пополнение баланса через СБП.

Используем REST: payment/rest/templates — createTemplate.do, getTemplateDetails.do, updateTemplate.do.

Симптом: createTemplate.do успешен (errorCode 0), QR в ЛК есть. getTemplateDetails.do с тем же templateId стабильно возвращает errorCode 5 «Доступ запрещён» (HTTP 200, отказ в JSON).

getTemplateDetails сейчас отправляем как application/x-www-form-urlencoded (поля templateId, userName, password, language; merchant на этот метод не передаём).

Просим банк: включить право на getTemplateDetails для API-логина или выдать отдельные креды; при необходимости прислать полный перечень обязательных полей для продуктива.

Идентификатор из ЛК (актуальный для сверки): BS1A003T9OBLQLD499DOHMC28RE9OHG7.
Ранее в переписке мог фигурировать другой пример templateId (черновик/другой тест) — в логах банка его могло не быть; ориентир — BS1A003… из кабинета и из ответа createTemplate.


--------------------------------------------------------------------------------
В) ОТКУДА МЫ БЕРЁМ ДАННЫЕ ДЛЯ СВЕРКИ С ЛК БАНКА
--------------------------------------------------------------------------------

— JSON-ответ createTemplate.do (поле templateId и весь объект), который отдаём из нашего backend после проксирования;

— журнал исходящих запросов нашего сервера на pay.alfabank.ru (URL, время; пароль в лог не писать открытым текстом);

— при включённом кеше — копия ответа create в БД по пользователю и templateId;

— ответ нашего API POST /api/auth/sbp-gateway/templates/details/ (внутри — ответ шлюза или кеш при errorCode 5).

Мы не видим ваш ЛК напрямую; templateId в ЛК и в ответе create — один и тот же объект.


--------------------------------------------------------------------------------
Г) СПРАВКА: НАШИ ENDPOINTЫ create / details (для внутренней команды / пояснений банку)
--------------------------------------------------------------------------------

POST /api/auth/sbp-gateway/templates/create/ — тело {"price": "1000.00"}; создаёт шаблон СБП QR через createTemplate.do; не проверяет факт оплаты.

POST /api/auth/sbp-gateway/templates/details/ — тело {"template_id": "<templateId>"}; проксирует getTemplateDetails.do; при errorCode 5 и наличии снимка в БД может вернуть source: cache.

Оплата: отдельно (getOrderStatusExtended / callback / другие сценарии); details не заменяет мониторинг платежа.


--------------------------------------------------------------------------------
Д) ЛОГИНЫ ДЛЯ КОРРЕЛЯЦИИ (пароли — только .env, в письмо не копировать)
--------------------------------------------------------------------------------

ALFA_PAYMENT_REST_BASE = https://pay.alfabank.ru/payment/rest

API: 45760700-api (+ пароль из .env)

Оператор / details (если заданы): 45760700-operator, переменные ALFA_TEMPLATES_DETAILS_USERNAME / PASSWORD

Терминал (если спросят): ALFA_TERMINAL_ID из .env

clientId (другой старый сценарий привязки карты): checkavto-m4


--------------------------------------------------------------------------------
Е) ЧЕРНОВИК: кассовая ссылка или динамический QR (если снова спросят)
--------------------------------------------------------------------------------

Используем статические шаблоны СБП QR через REST createTemplate.do (Альфа). Отдельно возможна постоянная ссылка СБП без динамического QR на каждую оплату. Динамически формируемый QR НСПК под каждую транзакцию на нашей стороне в основном сценарии не используем.


--------------------------------------------------------------------------------
Ж) ВНУТРЕННЕЕ (не обязательно отправлять банку)
--------------------------------------------------------------------------------

После успешного create сохраняем ответ в БД; при errorCode 5 на getTemplateDetails отдаём кеш клиенту — это обход, не замена доступа к getTemplateDetails.

Callback / статус оплаты по шаблону — согласовывать отдельно (getOrderStatusExtended, URL callback).
